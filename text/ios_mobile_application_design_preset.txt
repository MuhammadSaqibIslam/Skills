============================================================
iOS Mobile Application (Copy)
============================================================

Platform: ios
Description: Comprehensive design guidelines for iPhone applications following Apple Human Interface Guidelines. Covers safe areas, navigation bars, tab bars, touch targets, and iOS-native patterns.

────────────────────────────────────────────────────────────
1. Full Screen Layout
────────────────────────────────────────────────────────────
   Priority: must | Effort: s | Category: app-size

   App occupies the full screen. Design for logical resolution: 390 x 844 pt (iPhone 14/15 base). Use Auto Layout / flexible constraints. Design at 1x logical points, assets at 2x and 3x.

   Acceptance Criteria:
   • App occupies the full screen
   • Design for logical resolution: 390 x 844 pt (iPhone 14/15 base)
   • Use Auto Layout / flexible constraints
   • Design at 1x logical points, assets at 2x and 3x

   User Story: As a user, I want to see full screen layout applied in the interface, so that the application follows platform design guidelines consistently

────────────────────────────────────────────────────────────
2. Safe Areas
────────────────────────────────────────────────────────────
   Priority: must | Effort: s | Category: app-size

   Respect safe area insets on all edges. Content must not be hidden behind the Dynamic Island, notch, or home indicator. Top safe area: ~59pt (Dynamic Island) or ~47pt (notch). Bottom: ~34pt (home indicator). Use safeAreaInsets.

   Acceptance Criteria:
   • Respect safe area insets on all edges
   • Content must not be hidden behind the Dynamic Island, notch, or home indicator
   • Top safe area: ~59pt (Dynamic Island) or ~47pt (notch)
   • Bottom: ~34pt (home indicator)
   • Use safeAreaInsets

   User Story: As a user, I want to see safe areas applied in the interface, so that the application follows platform design guidelines consistently

3. Device Size Support
────────────────────────────────────────────────────────────
   Priority: must | Effort: m | Category: app-size

   Support all active iPhone sizes: iPhone SE (375x667pt), iPhone 14 (390x844pt), iPhone 14 Pro Max (430x932pt). Test on smallest and largest devices. Use flexible layouts that adapt to width differences.

   Acceptance Criteria:
   • Support all active iPhone sizes: iPhone SE (375x667pt), iPhone 14 (390x844pt), iPhone 14 Pro Max (430x932pt)

5. Status Bar
────────────────────────────────────────────────────────────
   Priority: must | Effort: l | Category: top-bar

   System status bar (time, signal, battery) is always visible. Adapt style (light/dark) to match content. Use .lightContent or .darkContent based on background color. Never hide the status bar in standard views.

   Acceptance Criteria:
   • System status bar (time, signal, battery) is always visible
   • Adapt style (light/dark) to match content
   • darkContent based on background color
   • Never hide the status bar in standard views

   User Story: As a user, I want to see status bar applied in the interface, so that the visual theme is consistent and comfortable to look at

6. Navigation Bar Height
────────────────────────────────────────────────────────────
   Priority: must | Effort: xs | Category: top-bar

   Standard navigation bar height: 44pt (below status bar). Total top area: status bar (~54pt with Dynamic Island) + nav bar (44pt) = ~98pt.

   Acceptance Criteria:
   • Standard navigation bar height: 44pt (below status bar)
   • Total top area: status bar (~54pt with Dynamic Island) + nav bar (44pt) = ~98pt

   User Story: As a user, I want to navigate using navigation bar height, so that I can find and access features intuitively

   Acceptance Criteria:

13. Modal Presentation
────────────────────────────────────────────────────────────
   Priority: must | Effort: s | Category: navigation

   Use modals (sheet style) for self-contained tasks: create, compose, settings. Dismiss via drag-down or close button. iOS 15+ uses .medium and .large detents for half/full sheets. Always include a close/cancel button.

────────────────────────────────────────────────────────────
   Priority: must | Effort: s | Category: navigation
